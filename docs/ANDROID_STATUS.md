# Android status

Last updated by the Android Firebase-removal pass. Read this before trusting the Android app.

## What changed

* **Firebase is gone** (Auth, Firestore, Cloud Messaging, google-services plugin, `FIREBASE_*`
  BuildConfig fields, ProGuard keep rule, manifest service/meta-data, `CloudRepository`,
  `DuoMessagingService`). `grep -ri firebase apps/android` returns nothing.
* **No accounts.** The app opens straight into the chat. Identity is a key pair held on the device;
  `uid = SHA-256 hex of the ECDH identity key` (same formula as `identityFingerprintHex` in
  `packages/protocol`). Cross-checked against vectors generated by the TypeScript protocol
  (`IdentityCodecTest`).
* **Wire format** follows `docs/CONNECTIVITY.md` and the protocol change: `hello` frames and
  manual connection codes carry `dhJwk` and `identityProof`. The receiver verifies the proof with the
  sign key and checks `uid == fingerprint(dhJwk)` before trusting anything.
* **Direct-only engine** mirroring `apps/desktop/src/lib/engine.ts`: pinned-peer pairing,
  safety-number confirmation, a peer that is not confirmed cannot inject messages, undelivered
  messages are queued (encrypted at rest) and resent whenever the channel opens.
* **Network settings** (STUN list, TURN URL/username/credential, `forceRelay`) in Settings, stored
  in SharedPreferences (not DataStore: no new dependency), applied to the next connection.
* **Real route reporting.** After the channel opens, `PeerConnection.getStats` is read, the
  nominated candidate pair is found and classified: host+host = same network, no `relay` =
  direct (NAT traversed), either side `relay` = relayed through TURN. Shown in Connection
  settings and in the chat header strip. Never inferred from configuration.
* **Room schema v3** drops `serverCreatedAt` / `syncedToCloud` (non-destructive 2→3 migration that
  rebuilds the table).

## What is NOT done

* **The mandatory 12-word recovery phrase is not implemented on Android.** There is no BIP-39 /
  recovery code in the Android tree (the earlier note that it exists was wrong). Android currently
  generates a random identity (software P-256 keys encrypted under a Keystore AES key). Restoring an
  identity on a new phone, or sharing one identity across desktop and Android, is not possible yet.
* No signaling relay, Nostr, store-and-forward, or automatic reconnect: connecting is by manual
  codes only (same as desktop today). BLE lives under `ble/` and is handled separately.
* Not tested across two real networks. The route reporter is only exercised by unit tests of the
  classification rules, not against a live TURN relay.
* No instrumented/UI tests; the Room migration has not been run on a device.
